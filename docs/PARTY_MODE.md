# 《卫戍协议·神人派对》玩法与实现说明

> 本文件是《卫戍协议·神人派对》在本仓库的实现说明：怎么开、怎么玩、规则边界、以及所有【测试值】。
> 设计依据是 `docs/development/design-full.txt` / `design-tables.txt`（《神人派对设计方案》讨论稿原文）。
> 本模式**不改动** PvE 战斗核心（`server/sim/`），它是在同一套房间、网络与重连之上另跑的一个对局引擎。

## 1. 这是什么

共同 PvE 守线 + 隐藏身份与秘密任务 + 卡牌驱动的有限 PvP + 公共市场 + 同步秘密行动 + 个人/阵营双层结算。

一局的结构（每轮循环）：

| # | 阶段 | 做什么 |
|---|---|---|
| 1 | 战报与事件 | 公开上一轮战果、战役状态、可公开的线索 |
| 2 | 抽牌与公共市场 | 抽 2 张牌；买 1 张固定价卡；对 1 张竞价卡提交一次密封报价 |
| 3 | 谈判与交易 | 与其他玩家交易资源（双方确认才生效） |
| 4 | 同步秘密行动 | 所有玩家同时提交卡牌与目标（超时＝不出牌） |
| 5 | 响应与反制 | 被影响者可提交 1 张反制卡（超时＝不响应） |
| 6 | 统一结算 | 服务端按固定优先级结算，产出公开战报与私人线索 |
| 7 | 共同战役 | PvE 主战场（由战役钩子给出结果） |
| 8 | 计分与线索 | 贡献、任务进度、嫌疑度、公开线索 |

古拉格在第 8 回合开放，见 §5。

## 2. 怎么开

1. 启动服务器（任选其一）：
   - 双击 `启动服务器-4040.bat`，或
   - `npm start`（默认 3000 端口），或
   - `set PORT=4173 && node server/index.js`
2. 浏览器打开对应地址，进入大厅 → 建立合作房间。
3. 房间底部的难度选择器旁边有 **「开启《卫冕协议·神人派对》模式」** 勾选框（房主可见）。
4. 勾选后补足座位（**4–20 人**，推荐 **8–12 人**），其他玩家点准备，房主开局。
5. 对局界面会自动切换为神人派对面板（不需要额外操作）。

命令行联机冒烟测试（需要服务器已在跑）：

```bash
node tools/party/smoke.mjs ws://127.0.0.1:4173/ws --players 8
```

它会真实建 WebSocket、开派对房、补 AI、开局，并校验隐藏信息隔离、幂等扣费与断线重连。

## 3. 房主设置（开局前，开局后锁定）

| 设置 | 取值 | 默认 |
|---|---|---|
| 派对模式 | 开 / 关 | 关 |
| 裂盟派互认 | `ALL` 全部互认 / `PARTIAL` 部分互认 / `NONE` 完全不互认 | `PARTIAL` |
| 额外挑战机会价格 | 1–10 张调度券 | 3【测试值】 |
| 主战场回合数 | 4–30 | 12【测试值】 |

服务端（`server/lobby.js` `setPartySettings`）、协议（`shared/protocol.js` `room.party`）与前端
（`public/js/screens/party.js` `PartyRoomSettings`）用同一套取值范围校验：非法值整条拒绝，不静默改写。

## 4. 身份、任务与资源

- 阵营：**忠诚派 / 裂盟派 / 投机派**，人数按 `shared/partyRules.js` 的 `factionTable` 分配（8 人＝5/2/1）。
- 每名玩家得到 1 张**秘密任务**与 1 张低分值**个人挑战**；任务按阵营过滤（裂盟派有专属任务）。
- 裂盟派互认由房主设置决定：全部互认 / 只认识一名指定队友 / 互不认识。
- 资源：**调度券**（买卡、竞价、资助）、**情报点**（调查、反制）、**影响力**（议案、指控）、**功绩**（排名）。
  初始值与每轮收入见 `PARTY_DEFAULTS.resources`【测试值】。
- **隐藏信息只在服务端**：身份、任务、他人手牌、他人报价金额、小游戏答案都不会出现在公共帧里。

卡池：24 张基础卡（整活 8 / 派对挑战 6 / 社交推理 6 / 反制 4），定义在 `shared/partyCards.js`。

每轮上限：最多打出 2 张主动卡 + 1 张反制卡；同一目标每轮最多承受 1 次高风险效果；
单次资源损失不超过目标可用资源的 25%（向下取整，至少 1）。

## 5. 古拉格（已确定规则，硬约束）

这些是用户明确要求、并在 `server/match/party/gulag.js` 与 `test/match/party-gulag.test.js` 中被逐条测试锁定的规则：

1. 古拉格采用**派对小游戏**挑战（反应 / 记忆 / 数字规律 / 真假判断，`minigames.js`）。
2. 挑战成功者进入「待返场」，**在下一次主战场结算时**统一返场（不在战斗中途加入）。
3. 队友只能**花调度券购买一次额外挑战机会**，不能直接替别人复活；受益者必须本人挑战并获胜。
4. 每名玩家正常情况下**只有一次**古拉格挑战资格；额外机会价格是配置项（默认 3 张券，【测试值】）；
   每名玩家整局最多被资助一次。
5. 古拉格正常情况下**在第 8 回合开放**。
6. **第 6 回合掷一次 D20**，只有**恰好等于 6** 才触发暴动。
7. 第 6 回合没触发、且古拉格仍开放时，**第 8 回合小游戏开始前再掷一次 D20**，仍然只有恰好 6 才触发。
8. 触发暴动后：所有在押者**立即获释**，下一次主战场结算时返场；古拉格**永久关闭**，
   本局不再接收新囚犯，也不能再购买或使用新的额外挑战机会；正在进行的挑战取消。
9. 第 6 回合已经触发暴动时，**第 8 回合不再掷骰**（监狱已永久关闭）。
10. D20 必须是**二十面骰**：不是 D6，触发条件也不是「大于等于 6」。

古拉格状态：未开放 / 开放 / 挑战中 / 待返场 / 已永久关闭。
囚犯状态：在押 / 挑战中 / 资格已用 / 待返场 / 已释放·待返场 / 已返场。
非法状态迁移被拒绝，因此不会重复释放、重复返场或重复奖励。

## 6. 胜负与计分

共同战役胜负、阵营胜负、个人排名**分开计算**：

- 忠诚派：战役胜利且裂盟派未渗透成功。
- 裂盟派：至少半数裂盟派完成破坏任务，并且（战役失败 或 有人完成 ≥2 次裂盟行动）。
- 投机派：不继承任何阵营胜利，只靠个人任务与排名。
- 个人总分**封顶 100**（战役 35 / 秘密目标 25 / 团队 25 / 派对 10 / 风险 5）【测试值】。

## 7. 服务端权威与防重

- 所有资源变动只有一个扣费点，且在各校验通过之后才发生。
- `g.party` 带 `requestId`，同一 id 只处理一次（跨阶段防重复提交）。
- 市场：每人每轮只能买 1 张固定价卡、只能报 1 次价；密封竞价**只在得标时扣费**，未中标者零损失。
- 结算按固定优先级（反制 → 侦查 → 交易 → 高风险 → 破坏 → 纯收益），不按消息到达顺序。
- 断线保留座位，重连补发公共帧与私密帧。

## 9. 已知限制

- 主战场（第 7 步）由一个战役钩子提供结果（`opts.campaign.roundInfo(round)`）。未提供钩子时，
  引擎会按 78% 成功率自动推演，供无战斗系统的联调使用；**没有**把派对规则接进 `server/sim/` 的真实战斗。
  这是刻意的：避免改动 PvE 战斗核心。
- 人机（AI）在古拉格按 60% 概率通过，不会打牌、不会交易——AI 只用于凑人数与占位。
- 界面的倒计时只是显示；阶段推进由服务端计时器决定。
- 音效、表情、观战席位尚未为派对模式单独适配。
